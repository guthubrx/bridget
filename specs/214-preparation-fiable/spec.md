# Session214 — préparation fiable des fournisseurs

Demande utilisateur : résoudre les refus répétés et proposer les programmes à l’installation. Réussite : le parent Claude natif attesté peut admettre Codex sur les machines autorisées sans perte de restriction ; les autres cas refusent avec une cause utile. L’installation propose Claude Code, Codex, Gemini CLI et Cursor CLI avec choix explicite ; aucun compte, token ni modèle n’est acheté ou copié.

Le cas réel213 porte une règle locale d’approbation T3, aucun launch_context, un preset d’outils complet, un callback attesté et un mode bypass. Cette règle ne constitue pas une permission à transmettre à une machine distante. Accepter uniquement ce cas fermé après preuve native ; ne pas neutraliser des règles arbitraires, hooks, refus d’outils, médiation humaine ou contexte absent non attesté. Garder mapping, annulation, pause et droits distants contrôlés.

Installation : choix explicite par option ou terminal interactif ; mode non interactif sans choix ne modifie aucun fournisseur. Installateurs officiels uniquement, compte utilisateur, installations existantes conservées. Gemini exige Node20/npm ; absence donne une action. Afficher programme présent/contrôle de support/connexion/modèles comme des faits distincts. Aucun démarrage de modèle pour détecter un programme. Une connexion personnelle restante n’est pas un accès qualifié.

Livraison : tests ciblés, revue indépendante, sources poussées, binaires distribués et images chargées vérifiées sur la flotte. Informer les propriétaires ; conserver les clés refusées avant tout rejeu exact autorisé. Aucun service Opus/NE02/Roadie.
