**La présence n'est pas SQL, mais elle peut être stable pendant la transaction.** `handle_control_state_set`, /Users/moi/Nextcloud/10.Scripts/64.bridget/.worktrees/159A-edition-file/crates/bridget-daemon/src/daemon.rs:12615–12653, tient Mutex<DaemonState> pendant le commit de contrôle puis l'enregistrement des interruptions. `TurnState`:21192–21208 tient le même mutex pendant `set_turn_state` et la reprise. `set_turn_state`:5229–5247 modifie les presences par &mut self. Ainsi, si le futur puits tient State depuis sa lecture d'attestation jusqu'au commit Immediate de `release_next_held`, ni pause traitée ni TurnState traité ne peut changer entre la vérification mémoire et le commit. Une attestation reste un fait observé : ce mécanisme ne rend pas instantanément connu un événement du fournisseur encore en transit.

**Ordre recommandé, sans modifier FR004 :** State → transaction SQLite Immediate ; présence attestée vérifiée dans ce segment critique ; relire control_state, EXISTS pause pending, échéances, tracked_requests et réservation dans cette transaction ; écrire held→dispatching et turn_gate ; commit ; construire DeferredControl ; libérer State ; prendre le verrou du writer pour push. Pas d'appel sur une autre connexion d'écriture tant que la transaction Immediate reste ouverte. Ne pas faire writer → State dans ce puits. Le commit est la linéarisation de la libération. Une pause/occupation traitée avant empêche la libération ; traitée après, elle n'annule pas un engagement déjà dispatching. Cela suit FR004 et la panne commit→push déjà assumée, sans prétendre que les gardes demeurent inchangées jusqu'au socket.

## Hypothèse3 : SC001 et nouveau flux d'attestation

SC001, /Users/moi/Nextcloud/10.Scripts/64.bridget/.worktrees/159A-edition-file/specs/159-edition-file/spec.md:174, dit « un envoi produit les mêmes octets, la même phase et la même poussée ». Sa portée est le chemin de remise au réglage fermé : enveloppe/canon, phase d'envoi, trame de remise et poussée. Elle ne dit pas que toutes les trames auxiliaires de connexion doivent rester identiques. FR023 exige justement la vérité/réattestation du signal de tour. Conditionner cette correction à held_queue afin de garder un faux repos global n'est donc pas imposé par SC001. Les nouveaux signaux TurnState sont une modification explicite de protocole de capacité ; leur trafic n'est pas un changement des octets du message. Le champ Register optionnel absent doit garder son wire, comme T006 le teste.

Limite documentaire : si « mêmes octets » était interprété comme comparaison de tout le flux socket, SC001 et FR023 seraient incompatibles. Il faut expliciter la portée message/remise dans la preuve d'égalité et annoncer le nouveau flux d'attestation, sans revendiquer byte-identité globale ni ignorer les suites de régression.
